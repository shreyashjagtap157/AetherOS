Preserve the architecture's central principle: abstract semantic contracts and authority boundaries while keeping implementation mechanisms replaceable wherever no real invariant requires them to be fixed. Distinguish semantic contract, authority and ownership, lifecycle and failure semantics, resource contract and physical allocation, implementation mechanism, platform/profile specialization, and observability/verification. Do not encode logical concepts as physical boundaries unless hardware, firmware, security, reliability or compatibility requires them. Do not create abstractions without a real purpose, and do not hardwire replaceable implementation details into public contracts.

The current architecture baseline contains several important semantic separations that must be audited and preserved unless properly changed through governance: UI semantic meaning is distinct from visual presentation and input routing; storage logical identity is distinct from physical layout and compatibility filesystem views; principal identity is distinct from privilege authority; Context meaning is distinct from execution priority and physical resource allocation; device semantics are distinct from physical resources and driver implementation. These are invariants at the contract level, not mandatory separate-process or separate-kernel boundaries. Internal optimization may combine implementations only if observable security, ownership, lifecycle, resource, compatibility and semantic guarantees remain intact.

The human-facing model is Context-centric. Context is the canonical human-facing unit of activity; applications remain deployment, runtime and security entities. Do not conflate Context ownership with application ownership, Workspace organization or security authority. Context lifecycle must not itself determine execution priority.
