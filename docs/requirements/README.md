# AetherOS requirements suite

Classification: Informative

This folder contains the reconstructed owner requirements, source provenance, engineering execution contract and profile reconciliation.

1. [User requirements baseline](USER_REQUIREMENTS_BASELINE.md) — mission, first usable release, whole-platform target and cross-system capability requirements.
2. [Source reconciliation](SOURCE_RECONCILIATION.md) — active/historical sources, authority boundaries and exact repository/CI snapshot.
3. [Owner working preferences and repository expectations](../project/OWNER_WORKING_PREFERENCES_AND_REPOSITORY_EXPECTATIONS.md) — preferred project workflow and expected system end state.
4. [Engineering execution and evidence](ENGINEERING_EXECUTION_AND_EVIDENCE.md) — primary integration authority, specialist process, status vocabulary, test and evidence rules.
5. [Profile model reconciliation](PROFILE_MODEL_RECONCILIATION.md) — deployment profiles versus device classes, hardware targets and experience shells.
6. [Historical source archive index](../project/ARCHIVE_INDEX.md) — preserved v1.0 architecture and earlier execution prompt.

The `AOS-UR-*` identifiers are traceability keys, not constitutional Requirement-IDs. A reconstructed requirement becomes normative only through the repository's governed architecture/ADR/RFC process.
