## 1. Scope

This RFC collects the conformance-test obligations for the Execution Architecture. It identifies which execution-level conformance tests are mandatory regardless of profile, the profile-specific subsets, and the reporting format.

This RFC is structural: it names tests and aggregates them. The tests themselves appear in the CTS executables.

---

## 2. Normative Requirements

### 2.1 Core Conformance

`RFC-0014.1`: Every implementation MUST pass the following Execution tests, regardless of profile:

- `CTS-EXEC-DOM-1` through `CTS-EXEC-DOM-6` (`RFC-0007`)
- `CTS-EXEC-DISP-1` through `CTS-EXEC-DISP-6` (`RFC-0008`)
- `CTS-EXEC-AS-1` through `CTS-EXEC-AS-6` (`RFC-0009`)
- `CTS-EXEC-IRQ-1` through `CTS-EXEC-IRQ-6` (`RFC-0010`)
- `CTS-SCHED-1` through `CTS-SCHED-6` (`RFC-0011`)
- `CTS-TIME-1` through `CTS-TIME-5` (`RFC-0012`)
- `CTS-CAP-MED-1` through `CTS-CAP-MED-7` (`RFC-0013`)

### 2.2 Profile-Specific Conformance

`RFC-0014.2`: Embedded profile additionally requires:
- Dispatch latency bound test at minimum clock speed (CTS-EXEC-DISP-EMB-1).

`RFC-0014.3`: Safety-Critical profile additionally requires:
- Bootstrap reproducibility full test (CTS-EXEC-DOM-6-SC).
- Deterministic scheduler proof artifact published (CTS-SCHED-SC-1).
- Interrupt priority ceiling protocol test (CTS-EXEC-IRQ-SC-1).

`RFC-0014.4`: HPC profile additionally requires:
- NUMA-aware scheduling test (CTS-SCHED-HPC-1).
- Scheduler deadline-admissibility proof for declared workload (CTS-SCHED-HPC-2).

### 2.3 Tier-Specific Conformance

`RFC-0014.5`: Every implementation claiming Tier A for a capability-related component MUST publish its formal verification artifacts alongside the conformance declaration.

`RFC-0014.6`: Every implementation claiming Tier A for the scheduler MUST publish the machine-checkable proof of the scheduling algorithm's bounded latency.

### 2.4 Reporting Format

`RFC-0014.7`: Execution conformance declarations MUST publish:
- Per-RFC test results (pass/fail/skipped with justification)
- Dispatch latency measurements for all execution units
- Scheduling algorithm class and proof reference
- Bootstrap reproducibility artifact ID (Safety-Critical)
- NUMA topology verification (HPC)

### 2.5 Failure Reporting

`RFC-0014.8`: Conformance failures MUST be classified per `Conformance-Test-Suite-Methodology.md` Section 10 and reported with CTS artifact IDs.

---

## 3. Conformance Tests

This RFC does not introduce new functional tests. It aggregates tests from RFC-0007 through RFC-0013 and profile-specific additions.

- `CTS-EXEC-CONF-1`: validates RFC-0014.1 — all core tests passed.
- `CTS-EXEC-CONF-2`: validates RFC-0014.2 — Embedded profile tests.
- `CTS-EXEC-CONF-3`: validates RFC-0014.3 — Safety-Critical profile tests.
- `CTS-EXEC-CONF-4`: validates RFC-0014.4 — HPC profile tests.
- `CTS-EXEC-CONF-5`: validates RFC-0014.6 — scheduler proof published.
- `CTS-EXEC-CONF-6`: validates RFC-0014.7 — reporting format.
