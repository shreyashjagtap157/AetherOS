# RFC-0008: Dispatch

**Status:** Active.
**Implements invariants:** I-1, I-3.
**Depends on:** RFC-0007 (Execution Domain), RFC-0011 (Scheduler).

---

## 1. Scope

This RFC specifies the *dispatch protocol*: the act of moving a thread or task from the scheduler decision to an execution unit (CPU core, hardware thread, or virtualized equivalent). Dispatch is the point where scheduling decisions become observable actions and where capability mediation (`RFC-0013`) enforces that the dispatching entity has the right to dispatch to the target.

This RFC does not specify the scheduling algorithm itself (RFC-0011), nor interrupt handling (RFC-0010).

---

## 2. Normative Requirements

### 2.1 Dispatch Entry

`RFC-0008.1`: Dispatch occurs on a decision by the scheduler (`RFC-0011`). The scheduler invokes the dispatch protocol with:
- Target thread or fiber identifier.
- Target execution unit.
- Required capability token demonstrating dispatch authority on the target execution unit.

### 2.2 Pre-dispatch Verification

`RFC-0008.2`: Before any thread is dispatched, the dispatch subsystem MUST verify that the capability token presented grants dispatch authority to the target execution unit. Failure to verify MUST abort dispatch.

`RFC-0008.3`: The dispatch subsystem MUST verify that the target thread's domain (`RFC-0007`) is compatible with the target execution unit's domain affinity. Incompatible domains MUST abort dispatch.

### 2.3 Address Space Activation

`RFC-0008.4`: When a thread is dispatched to an execution unit, the dispatch subsystem MUST activate that thread's address space (`RFC-0009`) on the target execution unit before the thread executes. Address space activation is atomic with dispatch: no instruction of the dispatched thread is visible to any other execution unit until address space activation is complete.

### 2.4 Dispatch Latency

`RFC-0008.5`: The dispatch operation (excluding scheduling decision time) MUST complete within a documented worst-case bound. This bound MUST be declared in the conformance declaration and MUST be verifiable by the CTS.

`RFC-0008.6`: No dispatch operation MAY block on I/O, memory allocation, or any operation that could cause unbounded delay. All blocking operations MUST occur before dispatch is invoked.

### 2.5 Migration

`RFC-0008.7`: A running thread MAY be migrated to a different execution unit. Migration requires the same pre-dispatch verification (RFC-0008.2, RFC-0008.3) and address-space reactivation. Migration MUST emit an event per `RFC-0031.17`.

`RFC-0008.8`: Migration of a thread holding locks shared with other threads MUST NOT violate the locking hierarchy declared in `RFC-0028`. Violations are non-conformant.

### 2.6 Preemption

`RFC-0008.9`: The dispatch subsystem MUST support preemption: a higher-priority dispatch decision MAY revoke a lower-priority thread's timeslot before its quantum expires. Preemption MUST emit a `ThreadPreempted` event per `RFC-0031.18`.

### 2.7 Idle

`RFC-0008.10`: When no runnable thread exists, the dispatch subsystem MUST enter an idle state and transition the execution unit to a declared power state. Exiting idle state MUST be triggered by a hardware interrupt or equivalent wake signal.

## 3. Dispatch State Machine

```
DISPATCH_IDLE
    │ scheduler decision
    ▼
DISPATCH_PREVERIFY — verify capability + domain
    │ success
    ▼
DISPATCH_ADDRSPACE_ACTIVATE — activate address space
    │ success
    ▼
DISPATCH_EXECUTE — thread running on execution unit
    │ preemption / migration / yield
    ▼
DISPATCH_SUSPEND
    │ re-dispatch or exit
    ▼
DISPATCH_IDLE or DISPATCH_EXIT
```

### 3.1 Dispatch States

| State                   | Description                                              |
|-------------------------|----------------------------------------------------------|
| `DISPATCH_IDLE`         | Execution unit available                                |
| `DISPATCH_PREVERIFY`    | Verifying dispatch authority and domain compatibility   |
| `DISPATCH_ADDRSPACE_ACTIVATE` | Activating address space on target execution unit |
| `DISPATCH_EXECUTE`      | Thread running                                           |
| `DISPATCH_SUSPEND`      | Thread descheduled mid-quantum                          |
| `DISPATCH_EXIT`         | Thread terminated; domain cleanup initiated             |

### 3.2 Transition Invariants

`RFC-0008.11`: The `DISPATCH_PREVERIFY → DISPATCH_EXECUTE` transition is atomic in the sense that no instruction of the target thread is visible until verification is complete.

`RFC-0008.12`: The `DISPATCH_ADDRSPACE_ACTIVATE → DISPATCH_EXECUTE` transition is atomic with respect to other execution units: no other thread may observe the target thread's address space until activation is complete.

## 4. Data Structures

```c
struct dispatch_authority {
    struct capability_token dispatch_cap;
    struct execution_unit_id target_unit;
};

struct dispatch_record {
    struct thread_id thread;
    struct execution_unit_id from_unit;
    struct execution_unit_id to_unit;
    uint64 dispatch_sequence_number;
    enum dispatch_outcome outcome;
};

enum dispatch_outcome {
    DISPATCH_OK             = 0,
    DISPATCH_CAPABILITY_FAIL = 1,
    DISPATCH_DOMAIN_MISMATCH = 2,
    DISPATCH_ASID_ACTIVATE_FAIL = 3,
    DISPATCH_PREEMPTED      = 4,
};
```

---

## 5. Failure Semantics

| Failure                  | Consequence                                            |
|--------------------------|--------------------------------------------------------|
| Capability verification fail | Dispatch aborted; event per RFC-0031.19        |
| Domain mismatch          | Dispatch aborted; event per RFC-0031.20               |
| Address space activation fail | Dispatch aborted; thread remains in scheduler queue |
| Preemption lock violation | Non-conformant; lock-order violation event emitted    |
