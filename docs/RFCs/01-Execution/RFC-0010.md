# RFC-0010: Interrupt Routing

Classification: Normative
Authoritative Source: RFC-0010.md
Requirement-ID: RFC-0010-000
Status: Proposed

**Lifecycle note:** Legacy text; treated as Proposed until evidence-gated acceptance.
**Implements invariants:** I-1, I-3.
**Depends on:** RFC-0007 (Execution Domain), RFC-0008 (Dispatch), RFC-0013 (Capability Mediation).

## 1. Scope

This RFC specifies how hardware interrupt signals are routed from source to handler within and across execution domains (`RFC-0007`). Interrupt routing is the mechanism by which hardware events reach software handlers while preserving domain isolation and capability mediation (`RFC-0013`).

This RFC does not specify the software interrupt handler protocol itself (that is `RFC-0026` for inter-component events).

---

## 2. Normative Requirements

### 2.1 Interrupt Domain Isolation

`RFC-0010.1`: An interrupt source is bound to a specific execution domain at configuration time. The binding is mediated by a capability token: only the holder of an `INTERRUPT_BIND` capability for the source may configure routing.

`RFC-0010.2`: Interrupt delivery MUST occur within the bound domain's context. An interrupt bound to domain A MUST NOT execute handler code in domain B without an explicit cross-domain interrupt delivery capability.

### 2.2 Routing Configuration

`RFC-0010.3`: Routing configuration is performed through a routing table maintained per execution domain. The table maps hardware interrupt vectors to handler capabilities. Each entry MUST specify:
- Hardware interrupt vector number.
- Handler capability token.
- Delivery mode (direct, queued, or coalesced).
- Priority relative to other interrupts in the same domain.

`RFC-0010.4`: Modifying the routing table requires `INTERRUPT_BIND` capability for the relevant source. Unauthorized modification is non-conformant.

### 2.3 Delivery Guarantees

`RFC-0010.5`: For interrupts declared as `direct` delivery, the handler MUST be invoked within a documented worst-case latency bound from interrupt assertion. This bound MUST be declared in the conformance declaration.

`RFC-0010.6`: For interrupts declared as `queued` delivery, the interrupt is queued and delivered at the next scheduler decision point. Ordering between queued interrupts MUST be preserved.

`RFC-0010.7`: For interrupts declared as `coalesced`, the platform MAY defer delivery if the interrupt fires at a rate exceeding the configured coalescing threshold. The coalescing policy MUST be declared.

### 2.4 Cross-Domain Delivery

`RFC-0010.8`: Cross-domain interrupt delivery requires a capability token that explicitly authorizes the delivery. The authorization path MUST be documented in the capability lineage (`RFC-0034`). Interrupt delivery that crosses a domain boundary without documented authorization is non-conformant.

### 2.5 Priority and Nesting

`RFC-0010.9`: Interrupt priority levels MUST be configurable. Higher-priority interrupts MUST preempt lower-priority handlers. Nested interrupts MUST be supported with a documented maximum nesting depth.

`RFC-0010.10`: The platform MUST define a minimum interrupt priority level at which interrupts are permitted to be masked by software. Masking at levels above this minimum is non-conformant for Safety-Critical profile.

### 2.6 Error Handling

`RFC-0010.11`: Spurious interrupts, misrouted interrupts, and interrupts arriving at a domain that has not configured a handler MUST be caught and reported through an event per `RFC-0031.22`. The system MUST NOT silently drop such interrupts without a record.

`RFC-0010.12`: Interrupt storm (an interrupt firing at a rate exceeding the coalescing threshold by more than a factor of 10) MUST trigger a `InterruptStormDetected` event per `RFC-0031.23` and MAY trigger automatic mitigation (e.g., coalescing threshold increase or interrupt masking).

## 3. Data Structures

```c
struct interrupt_vector {
    uint32                    irq_number;
    uint32                    domain_id;            // RFC-0007 domain identifier
};

enum interrupt_delivery_mode {
    DIRECT   = 0,
    QUEUED   = 1,
    COALESCED = 2,
};

struct interrupt_routing_entry {
    struct interrupt_vector   vector;
    struct capability_token   handler_cap;
    enum interrupt_delivery_mode mode;
    uint8                     priority;              // 0 = lowest
    uint32                    coalesce_threshold_hz; // relevant only for COALESCED
};

struct interrupt_routing_table {
    struct domain_id          domain;
    uint32                    entry_count;
    struct interrupt_routing_entry entries[];
};
```

## 4. Failure Semantics

| Failure                  | Consequence                                                |
|--------------------------|------------------------------------------------------------|
| Unauthorized routing change | Capability fault; routing table unchanged               |
| Spurious interrupt        | Event emitted per RFC-0031.22                             |
| Interrupt storm           | `InterruptStormDetected` event; mitigation triggered       |
| Priority inversion        | Non-conformant; Safety-Critical profile requires priority ceiling protocol |
| Maximum nesting depth exceeded | Platform-defined; handler returns with error flag     |
