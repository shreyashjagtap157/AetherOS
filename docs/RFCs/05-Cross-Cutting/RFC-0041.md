# RFC-0041: Conformance Test Suite Methodology (Cross-Cutting Supplement)

**Status:** Active.
**Implements invariants:** I-10, I-11.
**Depends on:** All RFCs.

---

## 1. Scope

This RFC supplements the top-level `Conformance-Test-Suite-Methodology.md` with cross-cutting conformance obligations that span multiple peer architectures. It does not replace the top-level methodology; it extends it.

---

## 2. Normative Requirements

### 2.1 Cross-Architecture Conformance Tests

`RFC-0041.1`: The following cross-architecture tests are mandatory for all profiles:

- `CTS-XS-ALL-1`: validates that every invariant I-1 through I-13 is satisfied by at least one component in every profile. An invariant with no satisfying component in a profile is a conformance violation.
- `CTS-XS-ALL-2`: validates that all five peer architectures are represented in the implementation. An implementation missing a peer architecture entirely (e.g., no Communication Architecture) is non-conformant.
- `CTS-XS-ALL-3`: validates that bootstrap path (`RFC-0007` Section 3) is reproducible from a cold start. Safety-Critical profile only.
- `CTS-XS-ALL-4`: validates that all declared RFCs have at least one conformance test per MUST requirement. An RFC missing CTS tests for a MUST requirement is non-conformant as a specification.

### 2.2 RFC-to-RFC Dependency Tests

`RFC-0041.2`: The following cross-RFC conformance tests are mandatory:

- `CTS-XS-DEP-1`: validates that capability revocation (`RFC-0039`) correctly propagates to capability transfer recipients (`RFC-0038`).
- `CTS-XS-DEP-2`: validates that lifecycle FSM transitions (`RFC-0018`) occur atomically within transaction commits (`RFC-0016`).
- `CTS-XS-DEP-3`: validates that capability mediation (`RFC-0013`) enforces address–authority orthogonality (I-13) for memory, endpoint, and object access.
- `CTS-XS-DEP-4`: validates that the scheduler (`RFC-0011`) receives correct blocking and wakeup notifications from synchronization primitives (`RFC-0028`).
- `CTS-XS-DEP-5`: validates that interrupt routing (`RFC-0010`) respects domain boundaries (`RFC-0007`) and capability bindings.
- `CTS-XS-DEP-6`: validates that the event model (`RFC-0031`) correctly attributes all events to their emitting domain and thread.

### 2.3 Invariant-to-RFC Mapping

`RFC-0041.3`: The following invariant-to-RFC mapping is normative:

| Invariant | Primary RFCs            | Mandatory test IDs                         |
|-----------|--------------------------|--------------------------------------------|
| I-1       | RFC-0013, RFC-0037       | CTS-CAP-MED-1, CTS-CAP-TOK-3              |
| I-2       | RFC-0007, RFC-0013, RFC-0037 | CTS-CAP-MED-3, CTS-EXEC-DOM-1        |
| I-3       | RFC-0013, RFC-0037       | CTS-CAP-MED-4, CTS-CAP-TOK-6              |
| I-4       | RFC-0016, RFC-0031       | CTS-STATE-TXN-2, CTS-OBS-EVT-3           |
| I-5       | RFC-0016                 | CTS-STATE-TXN-3, CTS-STATE-TXN-6          |
| I-6       | RFC-0015, RFC-0017       | CTS-STATE-OBJ-2, CTS-STATE-INT-2           |
| I-7       | RFC-0040                 | CTS-VERIF-4                               |
| I-8       | RFC-0040                 | CTS-VERIF-1, CTS-VERIF-3                  |
| I-9       | RFC-0002, RFC-0019       | CTS-COMP-MAN-4, CTS-STATE-PROV-3          |
| I-10      | All RFCs (per-RFC)      | Per-RFC conformance tests                  |
| I-11      | RFC-0005, RFC-0041       | CTS-COMP-PROF-1, CTS-CONF-ALL-1           |
| I-12      | RFC-0007                 | CTS-EXEC-DOM-4, CTS-EXEC-DOM-6            |
| I-13      | RFC-0037, RFC-0013       | CTS-CAP-TOK-6, CTS-CAP-MED-7              |

`RFC-0041.4`: Any implementation claiming conformance to this suite MUST satisfy all mandatory test IDs in the table above.

### 2.4 CTS Artifact Requirements

`RFC-0041.5`: Every CTS run MUST produce an artifact containing:
- CTS version and git commit
- Platform version
- Per-test result (pass/fail/skipped) with skip justification
- Test execution environment (hardware, OS, toolchain)
- Timestamp of execution

`RFC-0041.6`: A conformance declaration that does not cite a valid CTS artifact ID is non-conformant.
