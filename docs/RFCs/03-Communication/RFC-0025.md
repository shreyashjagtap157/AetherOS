## 1. Scope

This RFC specifies the *endpoint model*: how senders and receivers are identified, registered, and addressed in the Communication Architecture. An endpoint is a named, capability-protected communication terminal — analogous to a port in traditional networking, but capability-addressed rather than number-addressed.

---

## 2. Normative Requirements

### 2.1 Endpoint Identity

`RFC-0025.1`: Every endpoint has a fixed-length identifier computed from a hash of its domain, name, and declared capabilities. Endpoint identifiers are unique within an execution domain and are stable across restarts of the same component.

`RFC-0025.2`: Endpoints are capability-protected: registering an endpoint requires a `REGISTER_ENDPOINT` capability. Receiving on an endpoint requires a `RECV` capability for that endpoint.

### 2.2 Endpoint Registration

`RFC-0025.3`: An endpoint is registered with the Communication Architecture through an explicit registration call that declares:
- Endpoint name (string, up to 256 bytes)
- Maximum message size (bytes)
- Supported capability rights (which rights this endpoint may exercise on received messages)
- Handler capability (invoked on message receipt; `NULL` for polling mode)

`RFC-0025.4`: On registration, the platform returns a capability token for the endpoint. This token is required to send to or receive from the endpoint.

### 2.3 Endpoint Capabilities

`RFC-0025.5`: Endpoint capabilities are of the following kinds:

| Capability          | Authorized operations                        |
|---------------------|----------------------------------------------|
| `SEND`              | Send messages to this endpoint                |
| `RECV`              | Receive messages from this endpoint          |
| `QUERY`             | Read endpoint metadata without receiving     |
| `CLOSE`             | De-register this endpoint                    |
| `INHERIT`           | Transfer endpoint ownership                  |

`RFC-0025.6`: Each endpoint declares which rights it will grant to which incoming message classes. Rights derivation follows the algebra in `RFC-0043` (capability rights algebra).

### 2.4 Polling and Interrupt Modes

`RFC-0025.7`: An endpoint may operate in:
- **Handler mode** (default): messages are delivered to the declared handler capability; handler is invoked asynchronously.
- **Polling mode**: the receiver uses `RECV` to dequeue messages explicitly; no handler invocation.

### 2.5 Error Codes

`RFC-0025.8`: The following error codes are defined for Communication operations:

| Code | Name           | Meaning                                                     |
|------|----------------|-------------------------------------------------------------|
| 0    | `OK`           | Operation succeeded                                         |
| 1    | `ENODEST`      | No such endpoint                                            |
| 2    | `ENOCAP`       | Sender lacks required capability for this operation         |
| 3    | `EMSGSIZE`     | Message exceeds endpoint's declared maximum                |
| 4    | `ENOTCONN`     | Endpoint not in connected state                            |
| 5    | `ECAPSTALE`    | Capability presented has been revoked                      |
| 6    | `EPROTO`       | Malformed message format                                    |
| 7    | `EQUOTA`       | Endpoint receive quota exceeded                            |

`RFC-0025.9`: Error codes are returned in the `MSG_ERROR` response format per `RFC-0024.7`.

### 2.6 Endpoint Lifecycle

`RFC-0025.10`: An endpoint exists from its successful registration until it is explicitly closed or its owning domain is destroyed. Closing an endpoint with pending messages MUST be deferred until the queue is empty or the close is forced; forced close MUST emit an event per `RFC-0031.50`.

## 3. Data Structures

```c
struct endpoint_id {
    uint8_t bytes[32];          // BLAKE3-256 of (domain_id, name, cap_hash)
};

struct endpoint_registration {
    const char     *name;
    uint64          max_msg_size;
    uint8           supported_rights;   // bitmask of SEND/RECV/QUERY/CLOSE/INHERIT
    struct capability_token handler_cap; // NULL for polling mode
    uint8           mode;                // 0=handler, 1=poll
};

struct endpoint_metadata {
    struct endpoint_id id;
    struct domain_id   owner_domain;
    uint64             max_msg_size;
    uint64             queue_depth;       // current messages waiting
    uint64             queue_capacity;    // max queue depth
    uint8              registered_rights; // rights granted at registration
};
```
