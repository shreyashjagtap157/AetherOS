# RFC-0030: Communication Conformance

Status: Proposed

**Lifecycle note:** Legacy text; treated as Proposed until evidence-gated acceptance.

---

## 1. Scope

This RFC collects the conformance-test obligations for the Communication Architecture. It aggregates tests from RFC-0024 (Message Format), RFC-0025 (Endpoint Model), RFC-0026 (Routing), RFC-0027 (Capability Transfer), RFC-0028 (Synchronization), and RFC-0029 (Streaming), plus cross-communication conformance tests.

---

## 2. Normative Requirements

### 2.1 Core Conformance

`RFC-0030.1`: Every implementation MUST pass the following Communication tests, regardless of profile:

**Message Format:**
- `CTS-COMM-MSG-1` through `CTS-COMM-MSG-5` (RFC-0024)

**Endpoint Model:**
- `CTS-COMM-EP-1` through `CTS-COMM-EP-6` (RFC-0025)

**Routing:**
- `CTS-COMM-RT-1` through `CTS-COMM-RT-6` (RFC-0026)

**Capability Transfer:**
- `CTS-COMM-CAPX-1` through `CTS-COMM-CAPX-5` (RFC-0027)

**Synchronization:**
- `CTS-COMM-SYNC-1` through `CTS-COMM-SYNC-6` (RFC-0028)

**Streaming:**
- `CTS-COMM-STR-1` through `CTS-COMM-STR-5` (RFC-0029)

### 2.2 Cross-Communication Tests

`RFC-0030.2`: The following cross-cutting Communication tests are mandatory:

- `CTS-COMM-XS-1`: validates that capability tokens transferred in streaming chunks maintain integrity across multiple chunk deliveries.
- `CTS-COMM-XS-2`: validates that endpoint deregistration properly removes all routing table entries (`RFC-0026.10`) and sends `ENODEST` for all in-flight messages.
- `CTS-COMM-XS-3`: validates that a `LockOrderViolation` during a streaming operation does not corrupt the stream reassembly state.
- `CTS-COMM-XS-4`: validates that the `ECAPSTALE` error is returned for revoked capability tokens used as routing authorization.

### 2.3 Profile-Specific Conformance

`RFC-0030.3`: HPC profile additionally requires:
- Streaming flow control (`CTS-COMM-STR-4`) MUST pass with bandwidth-latency product measured and documented.

`RFC-0030.4`: Safety-Critical profile additionally requires:
- `CTS-COMM-SYNC-2` (priority inheritance) MUST pass with no inheritance chain exceeding depth 3.
- `CTS-COMM-SYNC-5` (lock-order violation detection) MUST be enabled and pass.

### 2.4 Reporting Format

`RFC-0030.5`: Communication conformance declarations MUST publish:
- Per-RFC test results (pass/fail/skipped with justification)
- Endpoint count and routing table size limits
- Maximum stream count per endpoint
- Synchronization primitive set implemented (which of the five from RFC-0028.1)

---

## 3. Conformance Tests

This RFC aggregates tests and declares the following cross-cutting tests:

- `CTS-COMM-CONF-1`: validates RFC-0030.1 — all core tests passed.
- `CTS-COMM-CONF-2`: validates RFC-0030.2 — cross-communication tests.
- `CTS-COMM-CONF-3`: validates RFC-0030.3 — HPC profile tests.
- `CTS-COMM-CONF-4`: validates RFC-0030.4 — Safety-Critical profile tests.
- `CTS-COMM-CONF-5`: validates RFC-0030.5 — reporting format.
