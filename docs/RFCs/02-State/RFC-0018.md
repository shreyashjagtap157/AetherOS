# RFC-0018: Lifecycle FSM

Classification: Normative
Authoritative Source: RFC-0018.md
Requirement-ID: RFC-0018-000
Status: Proposed

**Lifecycle note:** Legacy text; treated as Proposed until evidence-gated acceptance.
**Implements invariants:** I-4 (observable state transitions).
**Depends on:** RFC-0015 (Object Identity), RFC-0016 (Transaction Model), RFC-0031 (Event Model).

---

## 1. Scope

This RFC specifies the *lifecycle finite state machine (FSM)*: the mandatory state transitions that every persistent object traverses from creation to destruction. Lifecycle management transforms passive storage ("just bytes on disk") into managed persistent objects with explicit, auditable, observable lifetimes.

---

## 2. Normative Requirements

### 2.1 Lifecycle States

`RFC-0018.1`: Every persistent object occupies exactly one of the following states at any given time:

| State       | Description                                                        |
|-------------|--------------------------------------------------------------------|
| `Created`   | Object instantiated; content being formed; not yet valid          |
| `Validated` | Object content verified (`RFC-0017`); eligible for commit          |
| `Referenced` | Object is reachable through at least one named reference         |
| `Active`    | Object is actively serving reads and writes                        |
| `Cold`      | Object access frequency has dropped below the warm threshold      |
| `Archived`  | Object explicitly moved to archive storage tier                   |
| `Expired`   | A declared retention period has elapsed; awaiting cleanup        |
| `Destroyed` | Object explicitly deleted; identity preserved in history only    |

`RFC-0018.2`: The initial state of a newly created persistent object is `Created`.

### 2.2 Mandatory Transitions

`RFC-0018.3`: Every object MUST follow this mandatory transition path:

```
Created → Validated → Referenced → Active → Cold → Archived → Expired → Destroyed
```

`RFC-0018.4`: Transitions `Active → Cold` and `Cold → Archived` are automatic when configured thresholds are crossed. They are not optional but their timing is configurable per object.

`RFC-0018.5`: The `Referenced → Active` transition occurs when the first active read or write occurs against the object after its creation.

### 2.3 Transition Preconditions

`RFC-0018.6`: Each transition has declared preconditions. A transition MUST NOT occur unless all preconditions are satisfied:

| Transition              | Preconditions                                               |
|-------------------------|-------------------------------------------------------------|
| Created → Validated     | Integrity verification passed (`RFC-0017`)                  |
| Validated → Referenced  | Object identity assigned (`RFC-0015`)                        |
| Referenced → Active     | First active operation received                              |
| Active → Cold           | Access frequency below `warm_threshold` for `cold_cool_seconds` |
| Cold → Archived         | Access frequency below `archive_threshold` for `archive_wait_seconds` |
| Archived → Expired      | `retention_seconds` elapsed since `Archived` transition     |
| Expired → Destroyed    | Explicit delete request received; no held capabilities       |
| Any → Destroyed        | Compulsory deletion due to policy (e.g., legal hold expiry) |

`RFC-0018.7`: If a transition's preconditions are not met, the FSM MUST NOT transition the object. The attempt MUST be recorded as an event per `RFC-0031.41` with the attempted transition and reason for failure.

### 2.4 Rollback and Recovery

`RFC-0018.8`: If an object in `Active` state is found corrupted on next access, it MUST transition to `Created` (attempting re-validation from a replica) or to `Destroyed` (if unrecoverable). This is the only permitted backward transition.

`RFC-0018.9`: No other backward transitions are permitted. Forward-only lifecycle is a conformance requirement.

### 2.5 Observability

`RFC-0018.10`: Every lifecycle state transition MUST emit an event per `RFC-0031.42` containing: object identity, old state, new state, transition timestamp, and trigger (automatic vs. policy-initiated vs. explicit).

`RFC-0018.11`: The current state of every persistent object MUST be queryable by its identity (`RFC-0015`).

### 2.6 Policy Configuration

`RFC-0018.12`: The threshold parameters for automatic transitions (`warm_threshold`, `cold_cool_seconds`, `archive_threshold`, `archive_wait_seconds`, `retention_seconds`) MUST be configurable per object, per storage class, or globally. The platform MUST document the defaults and allow overrides.

`RFC-0018.13`: For Safety-Critical profile, automatic transitions from `Active` to `Cold` or from `Cold` to `Archived` are **forbidden** during any declared hazardous state. This restriction MUST be enforced by the lifecycle policy engine.

## 3. Lifecycle State Machine

```
     ┌──────────────────────────────────────────────────────────┐
     │                                                          │
     ▼                                                          │
Created ──→ Validated ──→ Referenced ──→ Active ──→ Cold      │
                                                    │            │
                                                    ▼            │
                                              Archived ──→ Expired
                                                               │
                                                               ▼
                                                          Destroyed
```

Arrows indicate only permitted forward transitions. The only permitted backward transition (recovery) is shown as a dashed line: `Active → Created` (only on unrecoverable corruption).

## 4. Data Structures

```c
enum lifecycle_state {
    LIFECYCLE_CREATED    = 0,
    LIFECYCLE_VALIDATED  = 1,
    LIFECYCLE_REFERENCED = 2,
    LIFECYCLE_ACTIVE     = 3,
    LIFECYCLE_COLD       = 4,
    LIFECYCLE_ARCHIVED   = 5,
    LIFECYCLE_EXPIRED    = 6,
    LIFECYCLE_DESTROYED  = 7,
};

struct lifecycle_policy {
    uint64    warm_threshold;           // accesses per second
    uint64    cold_cool_seconds;          // seconds below threshold before Cold
    uint64    archive_threshold;         // accesses per second for Archive
    uint64    archive_wait_seconds;      // seconds below threshold before Archive
    uint64    retention_seconds;         // seconds in Archived before Expired
};

struct lifecycle_transition_record {
    struct object_id        object_id;
    enum lifecycle_state     from_state;
    enum lifecycle_state     to_state;
    uint64                  timestamp_ns;
    uint8                   trigger;    // 0=automatic, 1=policy, 2=explicit
    uint8                   reason_code;
};
```

## 5. Failure Semantics

| Failure                  | Consequence                                                     |
|--------------------------|-----------------------------------------------------------------|
| Precondition not met     | Transition rejected; event per RFC-0031.41                       |
| Backward transition attempted (except Active→Created) | Non-conformant   |
| Hazard period transition (Safety-Critical) | Transition blocked; event per RFC-0031.43 |
| Object in Destroyed still referenced | Destroyed deferred until references cleared |
