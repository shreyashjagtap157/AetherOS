# RFC-0019: Storage Provider Interface

**Status:** Active.
**Implements invariants:** I-9 (replaceable mechanisms).
**Depends on:** RFC-0015 (Object Identity), RFC-0016 (Transaction Model), RFC-0017 (Integrity Model).

---

## 1. Scope

This RFC specifies the *storage provider interface*: the abstraction layer between the State Architecture's object model and the physical storage backends. The provider interface is how the State Architecture achieves I-9 (replaceable mechanisms) — changing the storage backend from NVMe to persistent memory to cloud storage to tape must not require changing the object model.

This RFC does not specify which storage providers must be supported. A conforming v1 implementation MUST declare at least one provider.

---

## 2. Normative Requirements

### 2.1 Provider Abstraction

`RFC-0019.1`: The State Architecture interacts with storage exclusively through the declared provider interface. It MUST NOT make assumptions about physical media, block size, latency, durability, or connectivity of the underlying provider.

`RFC-0019.2`: Every storage provider implements the following mandatory operations:
- `put(object_id, content)` — store content under identity
- `get(object_id)` — retrieve content by identity
- `delete(object_id)` — remove content (subject to lifecycle FSM)
- `list(prefix, limit)` — enumerate objects by identity prefix
- `get_metadata(object_id)` — retrieve storage metadata (size, tier, replica count)

### 2.2 Provider Registration

`RFC-0019.3`: Storage providers are registered with the State Architecture at platform initialization. A provider MUST declare its provider type and characteristics at registration:
- Media type (block, byte-addressable, object, tape, network)
- Capacity
- Latency bounds (minimum, typical, maximum)
- Durability level (expressed as estimated annual failure rate)
- Supported encryption modes

`RFC-0019.4`: A provider that cannot satisfy a requested operation (e.g., out of capacity) MUST return a structured error and MUST NOT corrupt state. The State Architecture decides fallback or escalation.

### 2.3 Tiering

`RFC-0019.5`: The provider interface MUST support tier assignment per object. Tiers represent cost/performance tradeoffs. The State Architecture MAY request that an object be moved between tiers; the provider MAY defer or refuse based on its own policy.

`RFC-0019.6`: The following tier levels are defined:
- `TIER_HOT` — lowest latency; highest cost
- `TIER_WARM` — moderate latency and cost
- `TIER_COLD` — high latency; lowest cost
- `TIER_ARCHIVE` — offline; highest latency; very low cost

### 2.4 Removability Test

`RFC-0019.7`: **The removability test**: Removing a storage provider MUST NOT cause any State Architecture invariant to be violated. If removing a provider causes the platform to violate any invariant, the provider MUST be in the trusted core, not optional.

`RFC-0019.8`: The following are examples of conformant optional providers:
- A compression provider that is bypassed if the provider fails
- A deduplication provider that continues operating if the dedup index is unavailable
- A replication provider that falls back to single-replica if the replica target is unreachable

### 2.5 Transaction Integration

`RFC-0019.9`: Storage providers participate in the two-phase commit protocol (`RFC-0016`). Each provider is a participant. Providers that cannot participate in two-phase commit MAY be used as write-through caches with a conforming primary provider handling transactions.

`RFC-0019.10`: Provider operations MUST be atomic at the provider level when the provider itself supports atomicity. Providers without native atomicity MUST be used only behind a transactionally-safe wrapper.

### 2.6 Provider Health

`RFC-0019.11`: Every provider MUST emit health events (`RFC-0031.44`) when:
- Capacity drops below 10% remaining
- Latency exceeds declared maximum by more than 50%
- Error rate exceeds declared threshold
- Provider goes offline

## 3. Provider Interface

```c
// Mandatory operations for every storage provider
struct storage_provider_ops {
    // Put content under identity. Returns 0 on success.
    int (*put)(struct storage_provider *prov,
               struct object_id id,
               const uint8_t *content,
               uint64 content_len,
               struct put_options opts);

    // Get content by identity. Returns 0 on success.
    int (*get)(struct storage_provider *prov,
               struct object_id id,
               uint8_t *buf,
               uint64 buf_len,
               uint64 *out_len);

    // Delete by identity. Returns 0 on success.
    int (*delete)(struct storage_provider *prov,
                  struct object_id id);

    // Enumerate by prefix.
    int (*list)(struct storage_provider *prov,
                struct object_id prefix,
                uint32 limit,
                struct object_id *results,
                uint32 *out_count);

    // Get storage metadata.
    int (*get_metadata)(struct storage_provider *prov,
                       struct object_id id,
                       struct storage_metadata *out_meta);
};

struct storage_provider {
    const char                   *name;
    uint8                         provider_type;
    uint64                        capacity_bytes;
    struct latency_bounds {
        uint64                    min_latency_ns;
        uint64                    typical_latency_ns;
        uint64                    max_latency_ns;
    } latency;
    float                         durability;     // 0.0 – 1.0 (annual uptime fraction)
    struct storage_provider_ops  ops;
    void                         *provider_state;
};
```

## 4. Failure Semantics

| Failure                  | Consequence                                                 |
|--------------------------|-------------------------------------------------------------|
| Provider capacity exhausted | Provider returns error; State Architecture may tier or reject |
| Provider latency exceeded | Health event per RFC-0019.11; fallback initiated          |
| Provider offline          | State Architecture fails over to replica; event per RFC-0031.45 |
| Non-participating provider used as primary | Non-conformant; must be behind transactionally-safe wrapper |
