# RFC-0017: Integrity Model

Classification: Normative
Authoritative Source: RFC-0017.md
Requirement-ID: RFC-0017-000
Status: Proposed

**Lifecycle note:** Legacy text; treated as Proposed until evidence-gated acceptance.
**Implements invariants:** I-6 (cryptographic integrity).
**Depends on:** RFC-0015 (Object Identity), RFC-0016 (Transaction Model).

---

## 1. Scope

This RFC specifies the *integrity model*: how every persistent object is cryptographically verifiable against its declared content-addressed identity. Integrity is the architectural mechanism that makes I-6 (cryptographic integrity) enforceable. It does not require trust in any single storage provider.

This RFC does not specify encryption (which is a storage policy), nor specific cryptographic algorithms (which are declared by implementation).

---

## 2. Normative Requirements

### 2.1 Merkle Structure

`RFC-0017.1`: Every persistent object in the platform is part of a Merkle Directed Acyclic Graph (DAG). The root of this DAG is the object identity (`RFC-0015`).

`RFC-0017.2`: For leaf objects (raw data), the identity is the hash of the object's content bytes.

`RFC-0017.3`: For composite objects (manifests, directories, transactions), the identity is the hash of the concatenation of:
- The object's own metadata
- The ordered list of child object identities
- A marker indicating the structure type

This forms a recursively verifiable tree.

`RFC-0017.4`: The platform MUST support at minimum 64 levels of Merkle tree depth. Depth beyond this MUST be declared in the conformance declaration.

### 2.2 Verification

`RFC-0017.5`: On every read of a persistent object, the platform MUST verify that the object's content matches its declared identity. Verification MAY be performed lazily (on first access) or eagerly (on write-commit), but it MUST be performed before returning data to a consumer.

`RFC-0017.6`: If verification fails, the platform MUST NOT return corrupted data. The platform MUST either:
- Reconstruct the object from a replica (`RFC-0015.13`), or
- Return an integrity fault per `RFC-0031.39` without exposing corrupted data.

`RFC-0017.7`: The platform MUST support incremental verification: when a child node changes, only the path from that child to the root needs recomputation. Full-tree recomputation on every update is non-conformant.

### 2.3 Signed Integrity

`RFC-0017.8`: The platform MUST support signed integrity: the root identity of any object graph MAY be signed by a declared signing key. The signing key MUST be identified by a key identifier in the object's metadata. Signature verification is independent of storage provider.

`RFC-0017.9`: Signature verification failures MUST be reported as `IntegritySignatureInvalid` per `RFC-0031.40` and MUST prevent the object from being used.

### 2.4 Auditability

`RFC-0017.10`: Every integrity verification result (pass or fail) MUST be recorded in the audit log (`RFC-0034`). Verification failures are never silently corrected without an audit record.

## 3. Data Structures

```c
struct merkle_node {
    uint8_t   hash[32];            // BLAKE3-256 of this node's content
    uint8     node_type;           // 0 = leaf, 1 = internal, 2 = directory
    uint64    child_count;          // 0 for leaf
    uint8_t   children[];           // array of child merkle_node hashes
    uint64    content_size;         // bytes of actual content at this node
};

struct signed_integrity {
    struct object_id          object_id;        // root of Merkle DAG
    struct key_identifier     signing_key_id;
    uint8_t                   signature[64];    // Ed25519 or equivalent
    uint8                     signature_algorithm; // declared
};
```

---

## 4. Failure Semantics

| Failure                  | Consequence                                                    |
|--------------------------|----------------------------------------------------------------|
| Content mismatch         | Reconstruction attempted; on failure, integrity fault delivered |
| Signature mismatch        | `IntegritySignatureInvalid`; object usage blocked             |
| Merkle path broken        | Integrity fault; event per RFC-0031.39                        |
| Unsigned root (when signing required) | Declaration required; silent unsigned is a profile violation |
