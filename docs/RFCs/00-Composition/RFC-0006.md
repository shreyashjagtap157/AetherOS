# RFC-0006: Composition Conformance

Classification: Normative
Authoritative Source: RFC-0006.md

Status: Proposed

**Lifecycle note:** Legacy text; treated as Proposed until evidence-gated acceptance.
**Implements invariants:** I-2, I-11.
**Depends on:** RFC-0002 through RFC-0005.

---

## 1. Scope

This RFC collects conformance-test obligations for the Composition Architecture. It identifies the composition-level conformance tests that are mandatory independent of profile (`Profiles-Specification.md`) and the profile-specific subsets that bind this RFC to `Profiles-Specification.md`.

This RFC is a structural RFC: it names conformance tests without redefining them. The tests themselves appear in the test executables named in the Conformance Test Suite methodology.

---

## 2. Normative Requirements

### 2.1 Core Conformance

`RFC-0006.1`: Every implementation MUST pass the following Composition tests, regardless of profile:

- `CTS-COMP-MAN-1` through `CTS-COMP-MAN-5` (`RFC-0002`).
- `CTS-COMP-RT-1` through `CTS-COMP-RT-4` (`RFC-0003`).
- `CTS-COMP-DEPR-1` through `CTS-COMP-DEPR-5` (`RFC-0004`).
- `CTS-COMP-PROF-1` through `CTS-COMP-PROF-4` (`RFC-0005`).

### 2.2 Profile-Specific Conformance

`RFC-0006.2`: Every implementation claiming a profile MUST pass the corresponding profile-subset tests in `Profiles-Specification.md` Section 4.

### 2.3 Tier-Specific Conformance

`RFC-0006.3`: Every implementation claiming a Tier A or Tier B (`RFC-0040`) for a Composition component MUST emit the relevant audit-log entry per `RFC-0034` showing the tier claim accompanied by supporting evidence IDs.

### 2.4 Reporting Format

`RFC-0006.4`: Conformance declarations referencing Composition tests MUST cite both the test ID and the latest executing artifact ID produced under the CTS.

### 2.5 Failure Forensics

`RFC-0006.5`: On test failure, the conformance-declaration MUST classify the failure per `Conformance-Test-Suite-Methodology.md` Section 10.

---

## 3. Alias Substitutes

`RFC-0006.6`: Substituted tests MAY replace the core conformance tests only when the substituted tests are at least as strict. Substitution MUST be documented in the conformance declaration and recorded via `RFC-0034`.

---

## 4. Reporting Obligations

Composition conformance declarations MUST publish:

- Component manifests tested.
- Profile declarations active during testing.
- Tier claims.
- Substitution table (if any).
- Failure forensics category counts.
- Test artifact IDs.

---

## 5. Conformance Tests

This RFC declares composition-level conformance but itself does not introduce new functional tests beyond the consolidated reporting requirements.

- `CTS-COMP-CONF-1`: validates RFC-0006.1 — all core tests passed.
- `CTS-COMP-CONF-2`: validates RFC-0006.2 — profile-specific subset passed.
- `CTS-COMP-CONF-3`: validates RFC-0006.4 — test artifact ID reported.
- `CTS-COMP-CONF-4`: validates RFC-0006.5 — failure forensics classified.

---

## 6. Verification Expectations

This RFC declares Tier B obligations. The Composition Root itself is Tier A per `RFC-0002`.
