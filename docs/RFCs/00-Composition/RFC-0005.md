# RFC-0005: Profile Selection

Classification: Normative
Authoritative Source: RFC-0005.md
Requirement-ID: RFC-0005-000
Status: Proposed

**Lifecycle note:** Legacy text; treated as Proposed until evidence-gated acceptance.
**Implements invariants:** I-11.
**Depends on:** RFC-0002, RFC-0004, `Profiles-Specification.md`.

---

## 1. Scope

This RFC specifies how a profile declaration (from `Profiles-Specification.md`) determines mechanism selection during composition and runtime. Profile selection is the mechanism by which I-11 declarable-profile invariant is enforced: a deployment's profile declaration is the basis for testing conformance.

This RFC does not redefine profile behaviour; it specifies selection semantics.

---

## 2. Normative Requirements

### 2.1 Profile Declaration

`RFC-0005.1`: A deployment MUST declare at least one profile in its conformance declaration.

`RFC-0005.2`: Profile declarations MUST enumerate: chosen profile(s), mandatory mechanism activations, optional mechanism activations, and forbidden-mechanism declarations.

### 2.2 Mechanism Resolution

`RFC-0005.3`: Given a profile declaration and a manifest (`RFC-0002`), profile-selection logic MUST:
- Activate every mandatory mechanism named in the relevant profile.
- Activate optional mechanisms named in the profile declaration.
- Reject manifests whose declared tiers conflict with the profile's tier minimums.

`RFC-0005.4`: If profile selection cannot be performed correctly, composition MUST fail per `RFC-0031.7` and MUST NOT instantiate.

### 2.3 Layered Extensions

`RFC-0005.5`: Optional layered extensions (e.g., capability-aware storage) MUST NOT be activated by profile selection unless explicitly declared. Defaults MUST NOT activate extensions.

### 2.4 Conflict Resolution

`RFC-0005.6`: Profile conflict (between declared profile features) MUST be resolved through the most restrictive profile applying.

`RFC-0005.7`: When the conformance declaration is incompatible with the manifest's declared tier expectations, profile selection MUST reject the manifest.

### 2.5 Boot-time Roles

`RFC-0005.8`: The Composition Root MUST load the deployment's profile declaration before instantiating any component and applies it to every subsequent instantiation.

`RFC-0005.9`: Profile selections MUST be auditable through `RFC-0034`.

---

## 3. Selection Algorithm

### 3.1 Inputs

- Deployment profile declaration.
- Component manifest.
- Tier expectations.

### 3.2 Decision

A binary decision for each (mandatory, optional, forbidden) mechanism. Optional mechanisms are activated if the manifest declares them.

### 3.3 Output

A profile-activation record per component including: chosen mechanisms, rejected mechanisms, and reasoning.

### 3.4 Complexity

`RFC-0005.10`: Selection MUST terminate in O(M) where M is the number of mechanisms considered per component.

---

## 4. Failure Semantics

| Failure                  | Consequence                                       |
|--------------------------|---------------------------------------------------|
| Profile conflict         | Component rejected, conflict event emitted         |
| Tier mismatch            | Component rejected                                |
| Manifest incompatible    | Component rejected                                |
| Selection success        | Component activated with chosen mechanisms        |

## 6. Verification Expectations
