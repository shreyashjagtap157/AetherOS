# IC-015: MMIO Capability Type Distinct from CAP_MEMORY

Implementation Contract ID: IC-015
Source Requirement: RFC-DRIVER-001.14, RFC-DRIVER-001.15, RFC-DRIVER-001.19 through RFC-DRIVER-001.22, RFC-0037 type 10
Owner: Driver Capability Broker; capability-mediator
Realised Invariants: I-1, I-2, I-13
Implementation Components: CAP_MMIO_REGION token (type 10); mmio_region_descriptor; MMIO access validation at access point
ABI / Behavioral Contract:
    CAP_MMIO_REGION token (type 10): target_object = mmio_region_descriptor { region_id, base_addr, size_bytes, access_width, access_rights, device_id, reserved }; rights field declares access widths/directions (bit 0 = read, bit 1 = write).
    MMIO capability authorises device register access, NOT backing physical pages as ordinary memory — distinct from CAP_MEMORY and CAP_DMA_MEMORY.
    Read-only MMIO capability MUST NOT be used for write; violations produce ECAPSTALE.
    MMIO capabilities domain-bound (CAPF_BOUND); not transferable unless DRV_HOTPLUG declared and transfer part of device handoff (RFC-DRIVER-001.22).
CTS Test: CTX-DRIVER-012, CTX-DRIVER-013
Formal Property: PF-DRIVER-005 — MMIO access requires MMIO capability distinct from CAP_MEMORY (I-1, I-13)
Observation Record: none
Status: DRAFT
