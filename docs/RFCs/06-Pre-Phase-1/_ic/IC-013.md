# IC-013: Driver Lifecycle FSM

Implementation Contract ID: IC-013
Source Requirement: RFC-DRIVER-001.3, RFC-DRIVER-001.4, RFC-DRIVER-001.5 through RFC-DRIVER-001.11
Owner: Driver Lifecycle Manager (`aether-state-model` reference)
Realised Invariants: I-1, I-2, I-4, I-10
Implementation Components: driver_state struct; lifecycle state enum; event emission at every transition; capability grant/suspend/revoke hooks
ABI / Behavioral Contract:
    States: Discovered → Loaded → Initialised → Operating → Unloaded; Faulted ← Operating; Faulted → Operating (recovery) or → Unloaded (replacement); Suspended → Operating (resume).
    Every transition MUST emit RFC-0031 event with: driver identity, old state, new state, transition timestamp, trigger reason.
    Discovered → Loaded: manifest matched, dependency resolver confirms prerequisites available.
    Loaded → Initialised: entry stub executes successfully; capability broker grants declared capabilities.
    Initialised → Operating: driver declares readiness (DriverReady event per RFC-0031).
    Operating → Faulted: unrecoverable fault; capabilities suspended (tokens valid but operations blocked).
    Faulted → Unloaded: recovery impossible or driver replaced; all capabilities revoked; driver destroyed.
CTS Test: CTX-DRIVER-003, CTX-DRIVER-004, CTX-DRIVER-005
Formal Property: PF-DRIVER-002 — all drivers follow declared lifecycle; no driver reaches Operating without passing through Initialised (VT-B); PF-DRIVER-003 — faulted driver capabilities suspended, not transferred (I-2)
Observation Record: none
Status: DRAFT
