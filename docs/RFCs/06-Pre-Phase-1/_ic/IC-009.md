# IC-009: Symbol Resolution Data Structures

Implementation Contract ID: IC-009
Source Requirement: RFC-COMPILER-001.41, RFC-COMPILER-001.42, RFC-COMPILER-001.43, RFC-COMPILER-001.44, RFC-COMPILER-001.45, RFC-COMPILER-001.46
Owner: Component loader; Composition Root (`aether-comp-model`)
Realised Invariants: I-10
Implementation Components: symbol_entry struct; symbol table format; GOT entry struct; load-time symbol resolver
ABI / Behavioral Contract:
    Component symbols classified as capability symbols or data symbols; distinguished by type field.
    Capability symbol value = offset into component's GOT where live capability handle is stored; data symbol value = offset into component's data region.
    Symbol resolution occurs at load time; Composition Root matches symbol name and type against exported symbols in the component's manifest (RFC-0002). Capability symbols resolved by granting the importing component a derived capability over the exporting component's capability slot.
    A symbol not declared in the manifest CANNOT be resolved — load-time error preventing component instantiation.
    Weak symbol semantics permitted for data symbols only; weak capability symbols NOT permitted (all capability symbol bindings strong, resolved at load time).
    Phase 1 minimum viable: static, load-time resolution; full dynamic linking deferred to Phase 3.
