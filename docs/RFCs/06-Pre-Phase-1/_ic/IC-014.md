# IC-014: Hot-Plug Capability Renegotiation Protocol

Implementation Contract ID: IC-014
Source Requirement: RFC-DRIVER-001.28, RFC-DRIVER-001.29, RFC-DRIVER-001.30, RFC-DRIVER-001.31
Owner: Driver Capability Broker; device registry
Realised Invariants: I-1, I-2, I-3, I-9, I-10
Implementation Components: DeviceAdded/DeviceRemoved events (RFC-0031); capability grant cascade; capability revocation cascade
ABI / Behavioral Contract:
    Device add: device registry creates device record; matching manifest located; broker grants capabilities based on device MMIO/interrupts/DMA; driver enters Discovered → Loaded → Initialised → Operating.
    Device remove: broker revokes all CAP_DEVICE_CONTROL/CAP_MMIO_REGION/CAP_DMA_MEMORY tokens for removed device; driver transitions to Faulted; if DRV_HOTPLUG, MAY re-discover; else → Unloaded.
    Hot-plug events emit DeviceAdded/DeviceRemoved with: device identity, driver identity, capability set changes, timestamp.
    New device capabilities isolated from existing drivers until explicitly granted — broker does NOT auto-grant to unrelated drivers.
CTS Test: CTX-DRIVER-006, CTX-DRIVER-007
Formal Property: PF-DRIVER-004 — device removal revokes all device capabilities within declared latency bound (VT-A)
Observation Record: none
Status: DRAFT
