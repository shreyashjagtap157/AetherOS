# IC-006: Component Entry Stub

Implementation Contract ID: IC-006
Source Requirement: RFC-COMPILER-001.18, RFC-COMPILER-001.19, RFC-COMPILER-001.20, RFC-COMPILER-001.21, RFC-COMPILER-001.50
Owner: Component runtime (`aether-runtime-model` reference); Composition Root (`aether-comp-model`)
Realised Invariants: I-4, I-12
Implementation Components: component_entry_block; entry stub assembly sequence; ComponentEntered event (RFC-0031)
ABI / Behavioral Contract:
    The entry stub executes before component application code, in order:
    1. Stack pointer validation — SP set to component's pre-allocated stack region; bounds validated against stack capability.
    2. TLS pointer initialisation — TLS pointer set to component's pre-allocated TLS region.
    3. Capability environment establishment — initial capability set loaded from component manifest slots; each capability verified by capability-mediator before placement.
    4. Root capability grant — component receives root allocation capability authorising heap allocation within declared bounds.
    5. Event emission — entry stub emits ComponentEntered event per RFC-0031.
    The entry stub is set up by the Composition Root (RFC-0007 Stage IV) or Minimum Executor (Stage II for bootstrap components); the component itself does NOT set up its own entry environment.
    The component's initial capability set is EXACTLY the set declared in its manifest — no ambient capability is available.
CTS Test: CTX-COMP-006
Formal Property: PF-COMP-003 — entry stub establishes capability environment exactly as declared (VT-C)
Observation Record: none
Status: DRAFT
