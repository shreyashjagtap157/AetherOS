# IC-004: Boot Allocator to Capability Transition

Implementation Contract ID: IC-004
Source Requirement: RFC-ALLOC-001.29, RFC-ALLOC-001.30, RFC-ALLOC-001.31, RFC-ALLOC-001.32
Owner: Minimum Executor; Capability Root (`aether-arch-riscv64` bootstrap)
Realised Invariants: I-12
Implementation Components: boot_allocator_record; origin_capability; BootAllocatorDecommissioned event emission (RFC-0031)
ABI / Behavioral Contract:
    Boot allocator: static fixed-size byte pool placed in ZONE_KERNEL at a known physical address; single-use during Stage II bootstrap; every allocation register-traced; regions not exposed to user-level components.
    Transition: after Capability Root constructs and seals the first CAP_MEMORY token (the origin allocation capability), the boot allocator is decommissioned; a BootAllocatorDecommissioned event is emitted; the boot allocator's physical pages are reclaimed into the page allocator free list.
    Transition is one-way and irreversible; no user-level component is instantiated before decommissioning.
CTS Test: boot-allocator decommission conformance (no dedicated CTX id in RFC-ALLOC-001 Section 6; covered by VT-A boot-allocator transition proof obligation)
Formal Property: PF-ALLOC-004 — no capability-free allocations survive beyond bootstrap (I-12)
Observation Record: none
Status: DRAFT
