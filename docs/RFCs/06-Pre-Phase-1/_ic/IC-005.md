# IC-005: Capability Passing Register Convention (RV64)

Implementation Contract ID: IC-005
Source Requirement: RFC-COMPILER-001.3, RFC-COMPILER-001.5, RFC-COMPILER-001.36, RFC-COMPILER-001.37, INTF-002
Owner: Compiler frontend / ABI specification (`aether-comp-model` reference)
Realised Invariants: I-1, I-2, I-13
Implementation Components: live handle type definition; register-to-handle mapping; generated call/return stubs
ABI / Behavioral Contract:
    Under the Software Capability Provider (Phase 1), a live capability is a pointer-width (RV64 XLEN), domain-local, generational handle into the provider-owned capability space.
    Handles use ordinary argument registers a0–a7 per generated function signatures; status and primary result follow the psABI-compatible result convention. No twelve-register token convention exists (RFC-COMPILER-001.37).
    Handles are caller-saved unless the architecture ABI says otherwise; preserving a handle preserves only a reference — provider validation of domain, slot generation, type, rights, and revocation state occurs on mediated use.
    Zero is the null handle. Freed slots advance their generation before reuse; truncated, stale, out-of-domain, or type-confused handles fail closed in bounded time.
    A compiler cannot mint authority: live handles originate only from the initial environment, a mediated return, explicit transfer/derivation, or validated canonical import (RFC-COMPILER-001.8).
CTS Test: CTX-COMP-001, CTX-COMP-002, CTX-COMP-003
Formal Property: PF-COMP-001 — capability registers are never implicitly created (I-2); PF-COMP-002 — ABI cannot be violated without hardware fault
Observation Record: none
Status: DRAFT
