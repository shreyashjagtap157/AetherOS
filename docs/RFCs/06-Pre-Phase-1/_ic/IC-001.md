# IC-001: Memory-Region Capability Token

Implementation Contract ID: IC-001
Source Requirement: RFC-ALLOC-001.11, RFC-ALLOC-001.12, RFC-ALLOC-001.15, RFC-ALLOC-001.16
Owner: Capability Authority Manager (`aether-cap-model`, `aether-capspace`)
Realised Invariants: I-1, I-2, I-13
Implementation Components: Capability Authority Manager allocation path; RFC-0037 token constructor and sealer; memory-region-descriptor encoding
ABI / Behavioral Contract:
    CAP_MEMORY token (type 1): target_object = memory_region_descriptor { region_id, base_paddr, size_bytes, page_size_class, numa_node, zone, flags, reserved }; rights = subset of RIGHT_READ | RIGHT_WRITE | RIGHT_EXECUTE.
    Construction: only the Capability Authority Manager may mint CAP_MEMORY tokens; each token sealed with the platform master seal key per RFC-0037.8.
    target_object holds an opaque memory region identifier, NOT a raw physical address — address resolution is the RFC-0009 mapping operation, preserving I-13 (capability grants authority; mapping resolves address).
CTS Test: CTX-ALLOC-001, CTX-ALLOC-005
Formal Property: PF-ALLOC-001 — no allocation capability may be created except by the Capability Authority Manager (I-2)
Observation Record: none
Status: DRAFT
