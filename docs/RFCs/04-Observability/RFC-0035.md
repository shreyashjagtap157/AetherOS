# RFC-0035: Diagnostic Query

**Status:** Active.
**Implements invariants:** I-4.
**Depends on:** RFC-0031 (Event Model), RFC-0032 (Trace Span), RFC-0033 (Replay Format).

---

## 1. Scope

This RFC specifies the *diagnostic query interface*: a structured mechanism for querying the event stream, trace spans, and replay log. The query interface is read-only; it does not modify system state. It enables operators, debuggers, and automated monitoring to inspect platform behaviour.

---

## 2. Normative Requirements

### 2.1 Query Language

`RFC-0035.1`: The diagnostic query interface MUST support a declarative query language with the following operators:

- **Filter** — select events matching predicates on any event field (event_class, event_type, emitter_domain, urgency, timestamp range, payload field values)
- **Project** — extract specific fields from matching events
- **Join** — correlate events from different sources (e.g., join events with trace spans by trace_id)
- **Aggregate** — count, sum, histogram, percentile over event properties
- **Window** — time-bounded queries (within N seconds of an event, for N specified)
- **Causality traverse** — given an event, return all events in its causal chain (using `causation_id`)

`RFC-0035.2`: Query predicates MUST be expressed in terms of event fields as defined in `RFC-0031.1`. Payload fields (event-type-specific) MAY be queried using dot notation (`event.payload.fieldname`).

### 2.2 Query Execution Modes

`RFC-0035.3`: The interface supports three execution modes:
- **Synchronous** — returns immediately with bounded result; suitable for small result sets.
- **Streaming** — returns a cursor; results are streamed as new matching events arrive; suitable for monitoring.
- **Historical** — executes over the replay log (`RFC-0033`); returns complete result set.

### 2.3 Query Limits

`RFC-0035.4`: All queries MUST be subject to declared limits:
- Maximum result set size (default: 1,000 records)
- Maximum query duration (default: 30 seconds)
- Maximum causal chain traversal depth (default: 100 events)

Queries that exceed limits MUST return partial results with a `RESULT_TRUNCATED` indicator and a `next_cursor` for continuation.

### 2.4 Predefined Queries

`RFC-0035.5`: The platform MUST provide predefined queries for the following common diagnostic scenarios:

- **Recent errors**: all events with `urgency >= 200` in the last hour
- **Thread activity**: all `ThreadStateChanged` events for a given thread_id in a time window
- **Capability lineage**: all `CapGranted` events for a given capability
- **Object lifecycle**: all lifecycle events for a given object_id
- **Domain traffic**: all message events for a given domain in a time window
- **Storage health**: all `ProviderOffline` and `ProviderHealthWarning` events in the last 24 hours

### 2.5 Query Attribution

`RFC-0035.6`: Every query execution MUST be itself logged as an event (`RFC-0031`) of class `Observability`. This creates an audit trail of who queried what and when.

### 2.6 Query Authorization

`RFC-0035.7`: Querying certain events requires declared capability rights. At minimum:
- Security-class events (0x0700) require a `QUERY_SECURITY_EVENTS` capability.
- Capability-class events (0x0200) require a `QUERY_CAPABILITY_EVENTS` capability.
- Raw event content (full payload) requires `QUERY_FULL_PAYLOAD`.

These capability rights are declared per component in the manifest (`RFC-0002`).

## 3. Data Structures

```c
struct diagnostic_query {
    uint8             query_type;              // FILTER, PROJECT, JOIN, AGGREGATE, WINDOW, CAUSALITY
    uint64            start_time_ns;
    uint64            end_time_ns;
    struct predicate  predicates[];           // conjunctive
    struct projection_fields fields[];        // for PROJECT queries
    uint8             execution_mode;         // SYNC=0, STREAMING=1, HISTORICAL=2
    struct query_limits {
        uint32         max_results;           // default 1000
        uint64          max_duration_ns;      // default 30s
        uint32          max_causality_depth;  // default 100
    } limits;
};

struct query_result {
    uint8              status;                 // OK=0, RESULT_TRUNCATED=1, QUERY_ERROR=2
    uint64             matched_count;         // total events matching
    uint64             returned_count;        // events in this result
    uint64             next_cursor;            // for continuation (if truncated)
    struct platform_event results[];           // actual result events
};
```

---

## 4. Failure Semantics

| Failure                  | Consequence                                               |
|--------------------------|-----------------------------------------------------------|
| Query timeout            | Partial results returned with `RESULT_TRUNCATED`          |
| Causality depth exceeded | Truncated with `max_causality_depth` reached              |
| Unauthorized query       | `ENOCAP`; event per RFC-0031.62                          |
| Unknown event class filter | Empty results; not an error                           |
